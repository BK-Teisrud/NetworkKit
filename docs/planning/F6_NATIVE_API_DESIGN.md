# F6 native API and ownership candidate

Working candidate, 2026-11-09, #90 / PR #177. Direct ordinary-app native networking targets iOS/iPadOS/macOS/tvOS under the owner decision. Proposed types below are absent on watchOS; HTTP Watch remains unchanged. No production signatures, default limits or native execution are approved here.

## Refinement precedence

The [discovery/QUIC contract refinement](F6_DISCOVERY_QUIC_CONTRACT.md) supersedes this earlier candidate where it specifies browser revisions/terminal overflow, remaining-credit versus active listener limits, SDK-observed multicast drops and separate QUIC stream/datagram ownership. All remain unapproved proposals; this is not a scope reduction or runtime proof.

## Common values and admission

NativeEndpoint describes an explicit host/port or opaque live Bonjour endpoint; it never resolves on initialization. NativeOperationTimeouts proposes connect=10, send=10, close=2 seconds; each finite/positive/at most 86400. Receive/accept/next-snapshot require an explicit timeout argument, avoiding an implicit unbounded waiter. NativeIOLimits requires positive maximumSendBytes and maximumReceiveBytes, at most Int32.max, with checked framing arithmetic. Per-operation byte bounds are not process-wide native-buffer guarantees.

Proposed error NativeConnectionError: invalidConfiguration, invalidInput, unsupportedCapability, duplicateOperation(direction), timeout(phase), transport(sanitizedDomain, code), messageTooLarge, malformedFrame, truncatedFrame, closed and limitExceeded(kind). Exact enum payload types remain to be written. CancellationError stays separate. No raw endpoint/payload description or unsupported permission diagnosis. A receive timeout/cancellation after admission terminates that connection; local invalid input does not. Same-direction operations fail immediately; one send and one receive may overlap. Closing is idempotent/shared and closes admission before waiting for cleanup.

## Proposed actor operations

| Actor | Candidate signatures | Value semantics |
| --- | --- | --- |
| TCPConnection | `static connect(configuration: TCPConfiguration) async throws -> TCPConnection`; `send(_ bytes: Data) async throws`; `receive(maximumBytes: Int, timeout: TimeInterval) async throws -> Data?`; `close() async` | nil = orderly EOF after any final bytes; empty data is not synthesized as EOF; failed sends have no delivery guarantee |
| DatagramConnection | `static connect(configuration: DatagramConfiguration) async throws -> DatagramConnection`; `send(_ datagram: Data) async throws`; `receive(timeout: TimeInterval) async throws -> Data`; `close() async` | Connected peer, one complete datagram; empty Data is valid; oversize/truncation fails rather than silently truncating; no delivery/order/retry guarantee |
| FramedConnection | `static connect(configuration: FramedConfiguration) async throws -> FramedConnection`; `send(_ payload: Data) async throws`; `receive(timeout: TimeInterval) async throws -> Data?`; `close() async` | Owns its stream from creation, cannot share with raw receive. Protocol parse errors terminate to avoid desynchronization |
| ServiceBrowser | `static start(configuration: ServiceBrowserConfiguration) async throws -> ServiceBrowser`; `nextSnapshot(after revision: UInt64? = nil, timeout: TimeInterval) async throws -> ServiceSnapshot`; `stop() async` | One waiter; latest bounded coalesced snapshot, not lossless events. First result is a ready/empty snapshot if no services; native callbacks update revision only on a real change |
| LocalListener | `static start(configuration: ListenerConfiguration) async throws -> LocalListener`; `accept(timeout: TimeInterval) async throws -> TCPConnection`; `endpoint() -> ListenerEndpoint`; `stop() async` | Bounded pending queue, exactly one active accept. App owns transferred connections; stop cancels pending/untransferred only |
| MulticastChannel | `static join(configuration: MulticastConfiguration) async throws -> MulticastChannel`; `send(_ datagram: Data) async throws`; `receive(timeout: TimeInterval) async throws -> MulticastDatagram`; `leave() async` | Explicit group/interface and bounded datagram queue; no membership/discovery scan or hidden unicast fallback |
| QUICConnection | Group/stream/datagram operations proposed in the refinement; native feasibility still pending | Do not publish a TCP-compatible send/receive facade before QUIC stream/datagram ownership, flow-control and accepted-stream limits are defined |

All configuration initializers are throwing and side-effect free. Startup operations return only after ready within their startup deadline or fail with cleanup. A waiting native path is not a ready connection and never waits indefinitely. Cancellation during a listener accept terminates only that accept waiter, not the listener, if native handoff state can be proven sound; otherwise return to explicit design review rather than silently changing ownership. The same applies to browser waiting: caller cancellation removes a waiter, not an already shared active browser. Per-connection I/O cancellation closes the connection as proposed above. Do not generalize WebSocket cancellation to unrelated discovery lifetimes.

## Configuration fields and fixed grammar

TCPConfiguration: endpoint, TLS selection, I/O limits, timeouts, peerToPeer=false, and explicit plaintext opt-in when TLS is not selected. TLS selection includes hostname/system trust and optional approved pins/identity only after adapter proof. DatagramConfiguration: peer endpoint, mandatory maximumDatagramBytes in 1...65507, timeouts, explicit plaintext acknowledgement; dynamic path MTU may impose a smaller size and results in an error. Plain UDP is never described as TLS-protected. A separate DTLS candidate would need a selected protocol and evidence; it is not secretly substituted for TLS.

FramedConfiguration owns a TCPConfiguration plus mandatory maximumPayloadBytes and maximumBufferedBytes. Prefix grammar: four-byte unsigned big-endian payload length, not including prefix; zero payload permitted; reject over-limit length before allocating body. Delimiter grammar: 1–16 raw bytes, delimiter excluded from returned payload, empty frames allowed, no escape mechanism; sending a payload containing delimiter fails locally. EOF with a partial prefix/body/delimiter record is truncatedFrame. Bound residual accumulation and native receive request size; do not read an unlimited native chunk then claim parser bounds cap native memory.

ServiceBrowserConfiguration: one valid explicit service type, local. domain only initially, mandatory maximumServices and maximumTXTBytesPerService, peerToPeer=false, bounded startup timeout. Proposal maxima: 1024 services and 4096 TXT bytes per service, app may choose smaller. The refined proposal terminates on result/TXT overflow instead of silently returning a partial set; native input memory remains outside SDK snapshot bounds. Opaque service IDs are scoped to one browser lifetime and are not a permanent device identity. ServiceSnapshot contains revision, bounded results and overflow/truncation indication; stale result endpoints are revalidated on connect. No TXT contents or service names in default diagnostics.

ListenerConfiguration: explicit loopback or app-selected local-interface binding (no default all-interface bind), optional concrete service advertisement, mandatory maximumPendingConnections and maximumConnections, TLS/identity configuration or explicit plaintext opt-in, and timeouts. Bounds at most 128 pending/1024 total candidate connections; arrivals over a bound are rejected before handoff. A pending connection consumes the total bound. Track active handed-off connections without taking ownership away from the app; a released/closed connection frees its lease exactly once. Stopping the listener frees pending leases but does not close already transferred connections. Restart creates a new listener, not reuse of stopped state. Exact interface identifier stability and supported native binding APIs remain feasibility questions.

MulticastConfiguration: one concrete multicast group/port, selected interface policy, mandatory maximumDatagramBytes and maximumPendingDatagrams (proposed at most 128), timeouts and explicit unencrypted/group-traffic acknowledgement. SDK-observed queue/validation discards are reported on the next receive; native pre-callback rejection and network loss remain unobservable. No global drop counter is promised. Native callback filtering and sender metadata are validated/sanitized; do not offer arbitrary source addresses as trusted identity. No entitlement bypass. Exact interface/membership and source-specific multicast coverage remain unresolved.

Peer-to-peer is an explicit Network.framework option attached to selected discovery/connection configuration. It does not authenticate a peer, guarantee a radio route, or imply support on all tvOS hardware. Native QUIC investigation must select ALPN, inbound/outbound stream model, stream/datagram count and byte limits, identity/trust, no implicit 0-RTT, and shutdown before signatures are finalized. These unresolved candidates remain in scope inventory and cannot be marked delivered from TCP tests.

## Before final exact API approval

Resolve interface binding feasibility, active-connection lease release without retained cycles, browser overflow semantics, multicast native loss accounting and QUIC model. Set all config value types/constructors/properties, result types and error enums without placeholders; compile ordinary public-import examples for each family. The signatures above are an actionable candidate, not a complete public header. Do not mark #90 complete or create a Ready implementation ticket while these boundaries are unresolved. No additional offline reserve slots were consumed by this document.

## Current QUIC feasibility boundary

The [completion investigation](F6_QUIC_COMPLETION_RESULTS_2026-11-09.md) verifies both stream directions and eight positive controls on one Mac source version. Empty datagram delivery and terminal handshake-error propagation remain unproved; complete mixed mode is blocked. Do not finalize a QUIC public contract that promises these behaviors from current prototype evidence. Keep the original requirements visible and review the adapter before proposing further execution or owner scope changes.

The owner subsequently approved the [logical startup/error direction](F6_QUIC_ADAPTER_REVIEW.md), explicitly no new code or execution. [Coordinator design](F6_QUIC_STARTUP_DESIGN.md) defines the next verification preparation; it does not retrospectively pass Q06/Q07 or resolve Q04/Q05.

The separately approved [startup experiment](F6_QUIC_STARTUP_RESULTS_2026-11-09.md) now verifies twelve Swift coordinator inputs and six latest native startup cases. This narrows logical-error/admission gaps without passing old native-code probes or resolving empty/mixed datagrams, resumption, callback bridge production safety or cross-platform API acceptance.

The separately approved [direct datagram comparison](F6_QUIC_DATAGRAM_ROUTE_RESULTS_2026-11-10.md) also failed complete empty delivery, despite successful nonempty delivery in both directions. It does not establish a universal OS limitation or an independent peer verdict. Raw empty/mixed requirements stay blocked and unchanged; no further identical rerun is justified without a new supported mechanism.
